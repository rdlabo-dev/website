# WebView Native UI Engine

**Web UIをネイティブレイヤーの上へ。**

_ネイティブからWebへのシームレスな投影で、見た目をつなぎます。_

![ネイティブサーフェスとWebViewコンテンツの上にWebオーバーレイを表示する概念図](docs/assets/hero.png)

_概念図です。オーバーレイの表示中は、ネイティブの外観をWebレイヤーに投影します。_

ネイティブコントロールとWebコンテンツが、スクロール画面、画面遷移、オーバーレイを共有するWebViewアプリを構築できます。

## WebViewの境界を越える

WebViewアプリは、Webの柔軟なレイアウトとネイティブプラットフォームの機能を組み合わせます。しかし、ネイティブUIとWebページは別々の描画レイヤーに存在します。WebViewの上に置いたネイティブコントロールは、DOMのスクロール、クリッピング、重なり順に自動では参加しません。Webモーダルの`z-index`を大きくするだけでは、その上に表示できません。

この境界を越えるには、ブリッジの呼び出し以上の処理が必要です。各プラットフォームの2つの描画システム間で、配置、外観、入力、描画、復元を調整しなければなりません。この連携をコンポーネントごとに作り直すと、本来便利なデザインの実現と保守に大きなコストがかかります。

WebView Native UI Engineは、その処理を再利用可能にします。アプリは、2つのレイヤー間で表示を移す仕組みを共有しながら、ネイティブUIをWeb主体の画面や操作と組み合わせられます。WebViewアプリで実現できることを広げ、実際に出荷できる形にすることが目的です。

## 実現できること

- **Webで設計した画面内のネイティブUI。** ネイティブのツールバー、タブバー、プレーヤーコントロール、対応するSDKビューを、アプリのDOMレイアウトやナビゲーションと組み合わせます。
- **ネイティブコンテンツと共存するWebオーバーレイ。** ネイティブサーフェスの上にモーダルなどを表示し、閉じたら操作可能なネイティブUIへ戻します。
- **ネイティブの外観を保つスクロールと画面遷移。** CSSでスタイルを再現せず、キャプチャしたネイティブサーフェスの外観をWebレイヤーの動きに追従させます。
- **コンポーネントとプラットフォーム間で共有する基盤。** 組み込みごとに独立して実装する代わりに、同じ投影と復元のライフサイクルをiOSとAndroidで再利用します。

## 仕組み

適切な場所ではライブのネイティブビューを使い、Webレイヤーが表示を所有する必要がある場合は、準備済みの見た目をDOMに投影します。再びネイティブ側へ戻せるようになったら、操作可能なネイティブビューを復元します。既存のDOMコンテナが、アプリのレイアウトとレイヤー構造の中でWeb投影の置き場所を決めます。

Engineはこのハンドオフを調整します。ビューの作成と配置は、引き続き組み込み側のレンダラーが行います。投影画像が保持するのは外観であり、ライブの操作や動画ではありません。キャプチャの可否とレイアウトの対応状況によって投影できる場面が決まり、使えない場合は明示的なフォールバックを適用します。詳細な契約と制約は、[概念と制約](docs/concepts.md)を参照してください。

## 始める場所を選ぶ

アプリは、Engineを組み込んだプラグインを通じてこれらの機能を利用します。プラグインの作者は既存のネイティブコントロールと公開APIを維持し、EngineがネイティブとWebの表示を連携させます。CapacitorまたはCordovaでiOSとAndroidに対応します。IonicとAngularは必須ではありません。

| 入口 | 目的 |
| --- | --- |
| [ドキュメント](docs/README.md) | 基本の初期化、任意の動作、高度なAPI、リファレンスの読む順序を案内します。 |
| [概念と制約](docs/concepts.md) | 投影がコンポーネントに適しているかを判断します。 |
| [基本的な初期化](docs/getting-started/initialization.md) | フレームワーク固有の組み込み前に、最小構成と必須入力を確認します。 |

ネイティブ登録がWebランタイムを起動するため、基本の組み込みに別のアプリ側Engine初期化関数は不要です。APIは1.0未満の段階です。npmとネイティブ依存で同じEngineバージョンを固定してください。Androidの配置はAPI 23以上、合成済みスナップショットはAPI 26以上で利用できます。
