# キャプチャのタイミングの設定

状態変更の成功が、その見た目のアニメーション終了より先に通知される場合に使います。たとえば、タブ選択イベントが届いた時点で強調表示がまだ拡大している場合、すぐにキャプチャすると、その途中の形が次のWebオーバーレイの下に残ります。コントロールが安定するまで、バックグラウンドでの準備を遅らせます。計測した外観がすでに安定していればデフォルトを維持してください。遅延を長くすると、以前の画像が利用可能な期間も長くなります。

`captureDelayMs`はCapacitorとCordovaに共通する任意の登録設定です。iOS、Android、低レベルの`createWebProjection`オプションでは、デフォルトは**50ミリ秒**です。値は有限の非負数でなければなりません。既存のデバウンスを使い、新しい更新や操作が発生すると、動作が落ち着いた後に準備を再開します。2つ目のタイマーを追加したり、オーバーレイの表示を遅らせたりはしません。

代替のピクセルが準備できるまで、最後に完成した画像を利用できます。完成した画像がなければ、通常のWebフォールバックを使います。デバウンス中にオーバーレイを開いても、新しいキャプチャを待ちません。このため、遅延を長くすると、更新後にも以前の外観が使われ得る期間が長くなります。

**UITabBarのLiquid Glass選択アニメーションでは、600 msを初期値として推奨します**。iOS 27.0のiPhoneとiOS 27.1のDuoシミュレーターでの比較では、50 msだと拡大した選択状態が写り、300 msでも小さな変化が残り、600 msでは1000 msで確認した安定後の外観と一致しました。これはその操作に対する推奨値であり、Appleが保証するタイミングでも、すべてのLiquid Glassに共通する時間でもありません。値を選ぶ前に、コントロールの選択、再選択、連続更新を計測してください。変化し続けるコンテンツでは、安定したスナップショットを保証できません。
